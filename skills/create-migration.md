# Skill: Create Migration
> Use this when modifying the database schema in Xenboox. Migrations are generated by Drizzle, never hand-written.

## Prerequisites

- Read `DATABASE.md` for schema reference
- Read `AGENTS.md` for Drizzle conventions
- Identify what tables/columns need to change

## Steps

### 1. Edit the Drizzle Schema File

Find the relevant schema file in `packages/db/schema/`:

```
packages/db/schema/
├── auth.ts              # users, accounts, sessions
├── organization.ts      # organizations, entities, user_entity_access
├── accounting.ts        # chart_of_accounts, journal_entries, journal_entry_lines
├── ap-ar.ts             # suppliers, invoices_ap, sales_invoices, etc.
├── treasury.ts          # bank_accounts, bank_transactions, reconciliations
├── cash.ts              # cash_accounts, imprest_floats, imprest_receipts
├── mobile-money.ts      # mobile_money_accounts, mobile_money_transactions
├── tax.ts               # tax records
├── documents.ts         # documents, document_links
├── audit.ts             # audit_log, agent_activity
└── helpers.ts           # shared column builders
```

### 2. Add or Modify Tables

```typescript
// packages/db/schema/{domain}.ts
import { pgTable, uuid, text, numeric, boolean, timestamp, pgEnum } from "drizzle-orm/pg-core"
import { sql } from "drizzle-orm"
import { entityId, timestamps, uuidId } from "./helpers"

// Create enum first (if new status values needed)
export const newStatusEnum = pgEnum("new_status", [
  "draft", "pending", "active", "completed", "cancelled"
])

// New table
export const newTable = pgTable("new_table", {
  id: uuidId(),
  entityId: entityId,
  name: text("name").notNull(),
  status: newStatusEnum("status").notNull().default("draft"),
  amount: numeric("amount", { precision: 15, scale: 2 }).notNull().default("0"),
  ...timestamps
})

// Adding a column to existing table
// Just add it to the table definition — Drizzle handles the migration
export const existingTable = pgTable("existing_table", {
  // ... existing columns ...
  newColumn: text("new_column"),              // nullable — safe to add
  // For required columns, provide a default:
  // requiredNewColumn: text("required_new").notNull().default("value"),
  ...timestamps
})

// Adding an index
export const newIndex = pgIndex("idx_new_table_entity")
  .on(newTable.entityId)
```

### 3. Generate the Migration

```bash
# From the repo root
pnpm db:generate
```

This creates a new migration file in `packages/db/migrations/`:

```
packages/db/migrations/
├── 0000_initial.sql
├── 0001_add_invoices.sql
├── 0002_add_mobile_money.sql      ← new file
└── meta/
    └── _journal.json
```

### 4. Review the Generated SQL

**Always review the generated SQL before applying.**

```sql
-- Example generated migration
CREATE TYPE "new_status" AS ENUM('draft', 'pending', 'active', 'completed', 'cancelled');

CREATE TABLE "new_table" (
  "id" uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  "entity_id" uuid NOT NULL REFERENCES "entities"("id"),
  "name" text NOT NULL,
  "status" "new_status" NOT NULL DEFAULT 'draft',
  "amount" numeric(15,2) DEFAULT '0',
  "created_at" timestamp NOT NULL DEFAULT now(),
  "updated_at" timestamp NOT NULL DEFAULT now()
);

CREATE INDEX "idx_new_table_entity" ON "new_table" ("entity_id");
```

Check for:
- Correct column types
- Correct defaults
- Foreign key references
- Indexes created
- No data loss (ALTER TABLE DROP COLUMN is destructive!)

### 5. Apply the Migration

```bash
# In development
pnpm db:migrate

# Or push directly (dev only, skips migration files)
pnpm db:push
```

### 6. Verify

```bash
# Open Drizzle Studio to visually verify
pnpm db:studio

# Run typecheck to ensure schema types match
pnpm typecheck
```

## Common Schema Patterns

### Every Financial Table

```typescript
export const financialTable = pgTable("financial_table", {
  id: uuidId(),                              // UUID primary key
  entityId: entityId,                        // Entity scoping (non-negotiable)
  // ... domain columns ...
  ...timestamps                              // created_at, updated_at
})
```

### Status Fields

```typescript
// ALWAYS use pgEnum
export const statusEnum = pgEnum("status", ["draft", "active", "completed"])

// NEVER use raw text
status: text("status")  // WRONG
```

### Numeric Amounts

```typescript
// Use numeric for money — never float
amount: numeric("amount", { precision: 15, scale: 2 }).notNull().default("0")
```

### Foreign Keys

```typescript
// With cascade delete for child records
moduleId: uuid("module_id").notNull()
  .references(() => moduleTable.id, { onDelete: "cascade" })

// Without cascade for reference-only
accountId: uuid("account_id").notNull()
  .references(() => chartOfAccounts.id)
```

### Indexes

```typescript
// Entity-scoped index (always)
export const entityIdx = pgIndex("idx_table_entity")
  .on(table.entityId)

// Composite index for common queries
export const statusIdx = pgIndex("idx_table_entity_status")
  .on(table.entityId, table.status)

// Date range index
export const dateIdx = pgIndex("idx_table_entity_date")
  .on(table.entityId, table.date)
```

## Dangerous Operations

### Column Drop

```bash
# NEVER drop a column without checking for references
# Drizzle won't generate DROP COLUMN — you must handle manually

# Before dropping:
# 1. Check for foreign key references
# 2. Check for application code using the column
# 3. Create a backup
# 4. Add the column to a "deprecated" list first
```

### Data Migration

```typescript
// If you need to migrate data (e.g., splitting a column):
// 1. Create new column
// 2. Write a data migration script
// 3. Add NOT NULL constraint after data is migrated
// 4. Remove old column in next migration

// packages/db/migrations/data-migrate.ts
import { db } from "@xenboox/db"

async function migrateData() {
  const rows = await db.select().from(oldTable)

  for (const row of rows) {
    await db.update(newTable)
      .set({ newColumn: transform(row.oldColumn) })
      .where(eq(newTable.id, row.id))
  }
}
```

## Common Pitfalls

1. **Hand-writing SQL migrations** — Always use `pnpm db:generate`. Review but don't write.
2. **Missing entity_id** — Every new table MUST have entity scoping.
3. **Using float for money** — Always `numeric(15,2)` for amounts.
4. **Raw string statuses** — Always `pgEnum`.
5. **Destructive changes without review** — DROP COLUMN, DROP TABLE, ALTER TYPE need careful review.
6. **Forgetting indexes** — Add indexes on entity_id and commonly queried columns.
7. **Not running typecheck** — Always run `pnpm typecheck` after migration.

## Verification

1. `pnpm db:generate` — migration file created
2. Review generated SQL — correct types, defaults, references
3. `pnpm db:migrate` — migration applied successfully
4. `pnpm db:studio` — new columns/tables visible
5. `pnpm typecheck` — no type errors
6. Test with existing data — no data loss
