# Pipeline 2: Bank Connection → Transaction Import → Categorization

## Sub-Part D — Propagation & GL Posting — Deep Audit

**Scope:** whether categorized bank transactions ever reach the general ledger, the bank-account → GL-account link, journal-entry creation from bank activity, TrustGuard validation on the path, and the Ledger Agent's posting discipline.

---

### 🔴 CRITICAL (1)

| #      | Finding                                                                                                                                                                        | Location                                                                                                                                | Impact                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **C1** | **Categorized bank transactions NEVER reach the general ledger.** Nothing in the entire repo creates a `journalEntries`/`journalEntryLines` row from a `bankTransactions` row. | Repo-wide (`grep insert(journalEntries)` = journal router, data-import-export, agent pipelines for assets/inventory/payroll/close only) | The entire Pipeline 2 — connection → import → categorize — ends with rows in `bank_transactions`. P&L, trial balance, and financial reports read **only posted journal entries** (`reports.ts`, `journal.ts getTrialBalance`). A company that connects its bank, imports, and auto-categorizes sees its money in the Banking tab but **zero impact on its financial statements**. The books are disconnected from the bank feed. Reconciliation only _matches_ bank tx to _existing_ JEs — it never creates the JE when none exists. This is the single biggest pipeline break. |

### 🟠 HIGH (3)

| #   | Finding                                                                                                                                                                                                                                                                                                                                |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | **Bank accounts have a `glAccountId` column but it is never assigned.** Schema has `bankAccounts.glAccountId` → chartOfAccounts (and `bankTransactions.glAccountId` → chartOfAccounts), yet no creation site (exchange-token, mono/plaid sync, bank-import, manual connect) sets it. There is no bank-asset account resolution at all. |
| H2  | **No deterministic propagation path exists to build the double-entry** — even if a caller wanted to post, they'd have to hand-build lines (bank side + category side), pick a period, validate, and link back. No shared helper, no tests.                                                                                             |
| H3  | **The Ledger Agent (`postEntry`) is never invoked by the bank pipeline.** Per AGENTS.md, "Ledger Agent is the only agent that posts to the general ledger" — but nothing in the bank import/sync/categorize flow calls it, and its `postEntry` only knows `PendingEntry` shapes from agent pipelines.                                  |

### 🟡 MEDIUM (3)

| #   | Finding                                                                                                                                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M1  | Category ↔ GL account mapping is incomplete: rules carry `glAccountId` (P2-C) but heuristic categories return `glAccountId: null` — propagation can't resolve an account for "Bank Fees" unless a rule exists. No category→default-account map or name-based resolution. |
| M2  | Reconciliation "finalize" simply writes `bookBalance = statementBalance` and `difference: "0"` with status "closed" — it asserts the books match the bank without ever verifying or posting anything. Silent fake assurance.                                              |
| M3  | No idempotency guard on JE-from-bank-tx: nothing checks `bankTransactions.journalEntryId` before creating a new JE (the column exists for exactly this purpose).                                                                                                          |

## Fix Plan — Sub-Part D

| #   | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | **Shared, tested propagation module** `packages/db/lib/bank-ledger.ts`: pure `buildBankJournalLines(tx, bankGlAccountId, categoryGlAccountId)` (deposit → Dr Bank / Cr Category; withdrawal → Dr Category / Cr Bank; transfer/fee direction rules), `resolveBankGlAccount(entityId, bankAccount)` (find entity's `asset/bank_account` COA row, else create one deterministically named after the account), `resolveCategoryGlAccount(entityId, category, ruleGlAccountId)` (rule wins, else name match against expense/revenue accounts). |
| F2  | **New tRPC mutation `banking.postToLedger`**: takes transactionIds; skips already-posted (`journalEntryId` set), uncategorized, or unresolvable; builds lines via F1; runs `validateJournalEntry` (TrustGuard) + period-open check; inserts JE (status `posted`, source `bank_feed`) + lines + links `journalEntryId` + audit trail; returns per-tx results with reasons. Entity-scoped throughout.                                                                                                                                       |
| F3  | **Assign `bankAccounts.glAccountId` at all creation sites** via the F1 resolver (exchange-token, mono/plaid sync, bank-import, manual connect).                                                                                                                                                                                                                                                                                                                                                                                           |
| F4  | **Call the propagation from the UI**: "Post to ledger" action in banking-view for categorized transactions (with the per-tx reason surfaced for skips).                                                                                                                                                                                                                                                                                                                                                                                   |
| F5  | Fix M2: finalizeReconciliation no longer fakes book balance — it verifies unreconciled count is 0 (or reports the true difference) before closing.                                                                                                                                                                                                                                                                                                                                                                                        |
| F6  | Fix M3: dedup is intrinsic to F2 (skip when `journalEntryId` set), plus a `reference` guard on the JE (`bank-tx-{id}`) so a duplicate can't be created even racing.                                                                                                                                                                                                                                                                                                                                                                       |
